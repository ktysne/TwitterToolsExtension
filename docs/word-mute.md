# ワードミュート

## やりたいこと

指定したワードや正規表現に一致する投稿を、検索やタイムラインから消す。

判定は `domhide.js`（ISOLATED world）だけで行い、レスポンスは変更しない。
ミュート一覧は拡張機能の保存領域と ISOLATED world の変数にだけ置き、MAIN world や共有 DOM に渡さない。
ページ側のスクリプトから一覧を直接読むことはできない。
非表示の DOM はページと共有するため、どの投稿を隠したかはページ側から観測できる。

## マッチの対象

投稿の本文を対象にする。
本文のテキストノードと画像の `alt` を連結して判定するため、絵文字も対象になる。
対象は article 内で `div[role="link"]` の外にある最初の `[data-testid="tweetText"]` である。

引用カード内の本文は対象にしない。
引用カード外の本文がない投稿は本文なしとして扱う。
リツイートでは、DOM に表示された元投稿の本文を対象にする。
アカウント検索などのユーザー単体のエントリも、ワードミュートの対象外である。

## マッチの規則

ワードは部分一致で判定する。
ワードと本文をともに小文字化して比較するため、大文字小文字は区別しない。

正規表現は1行に1つ書く。
各行を `new RegExp(行, "i")` でコンパイルするので、大文字小文字は区別しない。
コンパイルに失敗した行は無視し、他の行には影響させない。

ワードか正規表現のどれか1つでも一致すれば、その投稿を除外する。

## 設定の保存と受け渡し

ポップアップ（`popup.js`）は、入力欄の内容を1行ずつに分解し、`chrome.storage.local` の `muteWords` と `muteRegexes` に配列で保存する。
オン/オフは `wordMute` に持つ。

入力はそのまま（無効な正規表現も含めて）保存する。
無効な行は入力欄の下に警告として示すが、保存自体は妨げない。

`domhide.js`（ISOLATED world）が設定を読み、初期読み込み時と設定変更時にワードを小文字化し、正規表現をコンパイルして使い回す。
`bridge.js` はミュート一覧を読み出さない。

## @id ミュート

ワードではなく、投稿者のユーザー名（@id）でも投稿を消せる。

ブロック/ミュート除外（機能1, [search-filter.md](search-filter.md)）で消える相手は、改めて @id を登録しなくてよい。
@id ミュートは、ブロックもミュートもしていない相手を、ユーザー名を指定して消すための補助である。
投稿者のユーザー名は status リンクから取得する。

判定はユーザー名の完全一致で、大文字小文字を区別しない（保存時に先頭の `@` を取り除く）。
元投稿の著者と、リポストの文脈表示からリポストと判別できた場合のリポストした人を対象にする。
リポストした人は、リポストと判別できた `[data-testid="socialContext"]` 内またはそれを囲むプロフィールリンクから取得する。
いいねなど、リポストと判別できない文脈に表示された人物は対象外である。
アカウント検索やおすすめユーザーでは、`[data-testid="UserCell"]` のプロフィールリンクからユーザー名を取り、一致するセルを隠す。
プロフィールリンクは X の同一サービスの URL に限定し、検索や設定などの予約パスを除く。

オン/オフは `handleMute`、一覧は `muteHandles` に保存する。
`domhide.js` がこれらを読み、先頭の `@` を1つだけ外して小文字化した `Set` にして照合する。

@id は、ポップアップの入力欄に書くほか、投稿の ⋯ メニューの「この拡張機能でミュート」からも追加できる（`mutemenu.js`）。
⋯ をクリックした時点で対象投稿の著者を記録しておき、開いたメニューに X の項目を複製して差し込む。

## 除外の機構

ブロック/ミュート除外（[search-filter.md](search-filter.md)）は、引き続き `interceptor.js` が relationship に基づいてレスポンス段階で行う。
ワードミュートと @id ミュートは `domhide.js` が DOM 上で判定する。

3つの判定は独立してオン/オフできる。
ある判定を切っていても、他が有効ならその判定だけを行う。
DOM 上で隠した投稿は status リンクの投稿 ID、ユーザーセルは小文字化した handle の集合で累計を数える。
仮想スクロールで同じ対象が再描画されても二重に数えない。
ID や handle を取得できない対象は隠せても件数には含めない。
ルールの解除で累計を減らすことはなく、ページの再読み込みでリセットする。
件数は ISOLATED world の共有グローバルから `bridge.js` が取得し、relationship の除外累計（`data-tte-removed`）と合算してポップアップへ返す。
DOM 非表示の件数は DOM 属性に書かない。
ポップアップはトップフレームの累計だけを読む。

レスポンスからエントリを消す仕組みそのもの（`filterPayload`）は [architecture.md](architecture.md) を参照。

## 即時の反映（描画済み投稿）

`domhide.js` は `document_start` から Document を監視し、body がまだ無い場合にも対応する。
MutationObserver のコールバック内で、追加ノード自身・子孫・祖先の投稿とユーザーセルを同期判定する。
ルールの読み込み後に追加された一致投稿は、通常、次の描画前に隠す。
本文や href の変更を同期判定し、最初の変化から 250ms 後に 1 回走る間引き（スロットル）の全件走査で仮想スクロールの再利用を補う。
設定変更時には描画済みの対象を全件再評価する。

判定は DOM ベースで、本文は引用カード外の最初の `[data-testid="tweetText"]`、@id は投稿者リンクの先頭セグメントを見る。
ルールを外すと、隠していた投稿は元に戻す。
ブロック/ミュート（relationship）は DOM から判定できないため、この即時非表示の対象外である。

## 既知の制約

長文ツイートは DOM に出ている範囲の本文だけで判定するため、省略された部分のワードは展開されるまで判定できない。
外側の投稿に本文がない場合、引用カード内の本文は判定に使わない。
初期設定は非同期で読み込むため、読み込み完了より前の投稿が一瞬表示される可能性は残る。
X の DOM 構造が変わり、投稿者・リツイートした人・ユーザーセルのプロフィールリンクを取得できなくなると、その @id は判定できない。
本文を持たない投稿（画像だけの投稿など）は、本文へのワードミュートの対象にならない。
