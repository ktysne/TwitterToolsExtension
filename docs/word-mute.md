# ワードミュート

## やりたいこと

指定したワードや正規表現に一致する投稿を、検索やタイムラインから消す。

X 標準のミュートワードと違い、レスポンスの段階で投稿ごと取り除くため、画面には最初から出ない。

## マッチの対象

投稿の本文を対象にする。
具体的には `tweet.legacy.full_text`（無ければ `legacy.text`）と、長文ツイートの `note_tweet.note_tweet_results.result.text` を連結したものである。

引用ツイートの内側の本文や、リツイート元投稿の本文そのものは辿らない（X が付ける `RT @user: ...` のような本文は対象になる）。
アカウント検索などのユーザー単体のエントリも、ワードミュートの対象外である。

## マッチの規則

ワードは部分一致で判定する。
ワードと本文をともに小文字化して比較するため、大文字小文字は区別しない。

正規表現は1行に1つ書く。
各行を `new RegExp(行, "i")` でコンパイルするので、大文字小文字は区別しない。
コンパイルに失敗した行は無視し、他の行には影響させない。

ワードか正規表現のどれか1つでも一致すれば、その投稿を除外する。

## 設定の保存と受け渡し

ポップアップ（`popup.js`）は、入力欄の内容を1行ずつに分解し、`chrome.storage.local` の `muteWords` と `muteRegexes` に配列で保存する。
オン/オフは `wordMute` に持つ。

入力はそのまま（無効な正規表現も含めて）保存する。
無効な行は入力欄の下に警告として示すが、保存自体は妨げない。

`bridge.js`（ISOLATED world）は、これらを読み、`<div id="__tteMuteRules">` に次の形の JSON で書き出す。

```
{ "enabled": true, "words": [...], "regexes": [...],
  "handleEnabled": true, "handles": [...] }
```

`interceptor.js`（MAIN world）は、レスポンスのたびにこのノードを読む。
JSON 文字列が前回と変わったときだけワードを小文字化し、正規表現をコンパイルし直してキャッシュする。
毎回コンパイルしないため、高速スクロールでも負荷が増えにくい。

## @id ミュート

ワードではなく、投稿者のユーザー名（@id）でも投稿を消せる。

ブロック/ミュート除外（機能1, [search-filter.md](search-filter.md)）で消える相手は、改めて @id を登録しなくてよい。
@id ミュートは、ブロックもミュートもしていない相手を、ユーザー名を指定して消すための補助である。
投稿者のユーザーオブジェクト（`...core.user_results.result`）の `core.screen_name`（無ければ同じ階層の `legacy.screen_name`）にあり、レスポンスに必ず含まれるので確実に判定できる。

判定はユーザー名の完全一致で、大文字小文字を区別しない（保存時に先頭の `@` を取り除く）。
本人の投稿に加え、その人のリツイート（`retweeted_status_result` の著者）も対象にする。

ルールは `__tteMuteRules` の `handleEnabled` と `handles` に持つ。
`bridge.js` が `chrome.storage` の `handleMute` と `muteHandles` を読んで書き出し、`interceptor.js` が `Set` にして照合する。

@id は、ポップアップの入力欄に書くほか、投稿の ⋯ メニューの「この拡張機能でミュート」からも追加できる（`mutemenu.js`）。
⋯ をクリックした時点で対象投稿の著者を記録しておき、開いたメニューに X の項目を複製して差し込む。

## 除外の機構

ブロック/ミュート除外（[search-filter.md](search-filter.md)）、ワードミュート、@id ミュートは、同じ除外機構を共有する。
`interceptor.js` の `itemContentIsBad` が3つの判定を行い、いずれかに一致したエントリを取り除く。

3つの判定は独立してオン/オフできる。
ある判定を切っていても、他が有効ならその判定だけを行う。
除外した件数は、すべて合わせて `data-tte-removed` に積算する。

レスポンスからエントリを消す仕組みそのもの（`filterPayload`）は [architecture.md](architecture.md) を参照。

## 即時の反映（描画済み投稿）

`interceptor.js` の除外はレスポンスの段階なので、ルールを足した時点ですでに画面に出ている投稿には効かない（次にそのカラム/検索を読み込み直すまで残る）。
そこで `domhide.js`（ISOLATED world）が、ワード/@id ミュートのルール変更を `chrome.storage` の変化で受け取り、描画済みの `article` を走査して一致するものをその場で隠す。

判定は DOM ベースで、本文は最初の `[data-testid="tweetText"]`、@id は投稿者リンクの先頭セグメントを見る。
ルールを外すと、隠していた投稿は元に戻す。
ブロック/ミュート（relationship）は DOM から判定できないため、この即時非表示の対象外である。

## 既知の制約

リツイートは、本文が `RT @user: ...` の形になる場合があり、引用元の本文には一致しないことがある。
本文を持たない投稿（画像だけの投稿など）は、本文へのワードミュートの対象にならない。
