# TwitterToolsExtension

Twitter(現自称X)の使い勝手を補う Chrome 拡張機能です。

Twitter 本体の不具合の回避と、よく使う操作の追加をまとめています。

## 機能概要

### 1. ブロック/ミュート投稿の非表示

Twitter の検索設定「ブロックしているアカウントとミュートしているアカウントを除外する」が効かず、ブロックやミュートをした相手の投稿が検索結果に出てしまう不具合への対処です。

API レスポンスに含まれる関係情報(`relationship_perspectives` の `blocking` / `muting`)を見て、対象の投稿をレスポンスの段階で取り除きます。
画面には最初から表示されず、ブロック/ミュートした相手は自動的に消えます(手動登録は不要)。
検索だけでなく、ホームや返信などタイムライン全般に適用します。

### 2. 動画の自動再生を止める

タイムラインの動画がスクロールで勝手に再生される挙動を抑えます。

自動再生だけを止め、サムネイルをクリックしたときは通常どおり再生します。

### 3. メディアの保存

画像を含む投稿に保存ボタンを重ねて表示し、原寸画像を保存します(1 枚でも複数枚でも対象)。
動画を含む投稿には「動画を保存」ボタンを表示し、最高画質の mp4 を保存します。
1 投稿に動画が複数あるときは全部、画像と動画が混在するときも全部まとめて保存します。

保存先はブラウザのダウンロードフォルダ内の `TwitterMedia` です。

### 4. ワードミュート

指定したワードや正規表現に一致する投稿を、検索やタイムラインから取り除きます。

ワードは部分一致で、大文字小文字を区別しません。
正規表現は1行に1つ書け、こちらも大文字小文字を区別しません。
レスポンスの段階で投稿を消すため、画面には最初から出ません。

### 5. @id ミュート

指定した @id(ユーザー名)の投稿を取り除きます。

機能1で消し切れない相手を、ユーザー名で確実に消すための補助です。
本人の投稿に加え、その人のリツイートも対象にします。

@id は、投稿の ⋯(三点リーダ)メニューの「この拡張機能でミュート」からワンクリックで追加できます。
ポップアップの入力欄に直接書くこともできます。

### 6. コピーするリンクの整形

投稿の共有メニューの「リンクをコピー」でコピーされる URL から、共有元を示す追跡用パラメータ(`?s=20` など)を取り除きます。

X は `https://x.com/<user>/status/<id>?s=20` のように、どこから共有したかを示す `s` や `t` などのパラメータを付けてコピーします。
この機能は、コピーした瞬間にそれらを取り除き、`https://x.com/<user>/status/<id>` の素のリンクにします。

対象は「単一の X(x.com / twitter.com)の URL」だけで、取り除くのは追跡用の既知パラメータ(`s` / `t` / `ref_src` / `ref_url` / `cn` / `refsrc`)に限ります。
本文中の URL や X 以外の URL、検索の `q` などその他のパラメータには手を付けません。

## 導入手順

この拡張機能はストアに公開していないため、ソースコードをダウンロードして開発者モードで読み込みます。

### 1. ソースコードを入手する

Git に詳しくない場合は、GitHub から ZIP でダウンロードするのが簡単です。

1. GitHub のリポジトリページを開く。
2. 緑色の「Code」ボタンを押す。
3. メニュー下部の「Download ZIP」を選ぶ。
4. ダウンロードした ZIP ファイルを、任意の場所に展開(解凍)する。
   - 展開すると `TwitterToolsExtension`(末尾に `-main` などが付くことがあります)というフォルダができます。このフォルダの中に `manifest.json` が入っていることを確認してください。

Git を使える場合は、リリースのタグを指定して取得することもできます。

```
git clone https://github.com/ktysne/TwitterToolsExtension.git
```

### 2. Chrome に開発者モードで読み込む

1. Chrome で `chrome://extensions` を開く。
2. 右上の「デベロッパーモード」をオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」を押す。
4. 手順1で展開した、`manifest.json` を含むフォルダを選ぶ。
5. すでに開いている x.com のタブは再読み込みする。

読み込み時に「ダウンロードの管理」の権限確認が出ます。
これは機能3(メディア保存)で `chrome.downloads` を使うためです。

ZIP を展開したフォルダごと削除したり移動したりすると拡張機能が読み込めなくなるため、消さない場所に置いてください。更新する際は、新しい ZIP を展開し直して、`chrome://extensions` の拡張機能カードにある更新(再読み込み)ボタンを押します。

## 使い方

ツールバーの拡張機能アイコンを押すと、6 つのトグルが出ます。
いずれも既定でオンです。

- ブロック/ミュート投稿を非表示
- 動画の自動再生を止める
- 画像/動画に保存ボタンを表示
- コピーするリンクを整える
- ワードでミュート
- @id でミュート

トグルの変更は開いている x.com のタブへ反映します(再読み込み不要)。
ただし反映の範囲は機能によって異なります。すべての機能は、変更後に新しく読み込まれる投稿へ反映します。
ワード/@id ミュートはさらに、すでに描画済みの投稿もその場で再評価して隠します。
ブロック/ミュート投稿の非表示は、関係情報が DOM から判定できないため、描画済みの投稿には効かず、次にそのカラム/検索を読み込み直したときから反映します。

メディア保存は、対象の投稿の右上に出るボタンを押すだけです。ボタンには保存される件数が出ます。

ワードミュートは、ポップアップの入力欄に、ミュートしたいワードと正規表現を1行に1つずつ書きます。
入力はそのまま保存され、開いている x.com のタブへ即座に反映します(描画済みの投稿も再評価して隠します)。
無効な正規表現は入力欄の下に警告として示し、その行だけ無視します。

@id ミュートは、投稿の ⋯ メニューの「この拡張機能でミュート」から追加するか、ポップアップの入力欄に @id を1行に1つずつ書きます(@ は省略可)。
追加した投稿は、次にその検索やタイムラインを読み込んだときから消えます。

## 動作確認の状況

- ブロック/ミュート非表示: 実環境で、ブロック/ミュートした相手が検索結果から消えることを確認済み(通常の表示でも、複数カラムの表示環境でも)。
- 自動再生の停止: 実環境でスクロール中の自動再生のブロックと、クリックでの手動再生の維持を確認済み。
- メディア保存: 画像URLの原寸化(`name=orig`)を実DOMで確認。動画は1投稿の複数本を一括保存できることを確認済み。
- @id ミュート: 実環境で、指定した @id の投稿が検索結果から消えることを確認済み。
- コピーするリンクの整形: 実環境で「リンクをコピー」が `document.execCommand("copy")` を使い、選択文字列に `?s=20` 付きの URL が入ることを確認。copy フックで実際のクリップボードが素のリンクに整形されること、トグル OFF で無効化されることを確認済み。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | 拡張機能の定義(権限、コンテンツスクリプト、background) |
| `interceptor.js` | ページの MAIN world で動く。fetch/XHR のフック(投稿の除外・動画URL収集)、動画再生のフック、コピー時のリンク整形(copy/クリップボードのフック) |
| `bridge.js` | ISOLATED world。設定とミュートのルールを MAIN world へ橋渡し |
| `imagesave.js` | ISOLATED world。保存ボタンの設置とURL収集 |
| `mutemenu.js` | ISOLATED world。⋯ メニューへの「拡張機能でミュート」項目の追加 |
| `domhide.js` | ISOLATED world。ルール変更時に描画済みの該当投稿を即時非表示 |
| `background.js` | service worker。`chrome.downloads` で保存を実行 |
| `popup.html` / `popup.js` | ツールバーの設定パネル |
| `test/` | `node:test` による単体テスト(外部依存なし) |
| `package.json` | `npm test`(= `node --test`)の定義 |

## テスト

ロジックの中核(レスポンスのフィルタ、保存URL/パスの検証、保存名の組み立て)は、
DOM に依存しない純粋関数として切り出し、Node 標準のテストランナーで検証しています。
外部依存はありません。

```
npm test        # = node --test（Node 18 以降）
```

詳細は [docs/testing.md](docs/testing.md) を参照してください。
